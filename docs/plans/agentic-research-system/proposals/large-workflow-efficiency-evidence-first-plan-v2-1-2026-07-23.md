## 2. Purpose and assurance floor

The programme aims to reduce avoidable context replay, repeated evidence work, and
workflow friction without weakening:

1. mathematical, statistical, research-design, result, or claim assurance;
2. exact-state and provenance binding;
3. independent review against the exact subject and direct authorities;
4. canonical writer, transition, and evidence-set ownership;
5. immutable accepted artifacts and external lifecycle records;
6. every validation required by the accepted obligation/dependency graph; or
7. owner approval boundaries.

No historical token or time saving has been established. The approximately 80k,
30%-45%, and 50% claims are withdrawn. One pilot may establish operability only. Any
quantitative efficiency claim requires a separately accepted evaluation protocol.

The controls retained from the historical programme are standalone/APM separation,
exact-state continuity, fresh no-parent-history review, canonical-authority fail-closed
checks, certify-before-regenerate, the P-039 research-value/lifecycle gate, focused
independent validation, explicit owner gates, and a stop before a third ordinary cycle.

The reusable write lease, generic validation cache, author-defined exhaustive review
manifest, universal token threshold, and producer-authored efficiency verdict remain
rejected.

## 8. Privacy-safe telemetry acquisition contract

### 8.1 Inputs and path authority

Default input is `session_id` plus an opaque `root_id` from the owner-approved session
root registry. The default registry is limited to the configured Codex active-session
and archived-session roots. Reports emit only the root ID, never the resolved path.

A literal path is rejected unless Stephen supplies a private, acquisition-specific
override. The committed record carries an opaque override ID and verdict, not the path.
Resolution must bind the final opened-file identity and prove containment in the chosen
root. Root escapes and reparse points are rejected unless the owner override explicitly
accepts the exact final identity. Failure to obtain a stable file identity is a failure,
not a warning.

### 8.2 Single-handle stable-prefix algorithm

For each admitted session:

1. Resolve the session under the selected root and open one read-only handle.
2. Bind root ID, session ID, final file identity, initial length, and acquisition time.
3. Select the last complete newline at or below the initial length. Bytes after it are
   outside the frozen prefix.
4. Stream exactly that prefix from the same handle. In the same pass, compute SHA-256,
   parse structural allowlisted records, and derive metrics.
5. Rewind the same handle, recompute the exact prefix digest without deriving metrics,
   and require equality with the first digest.
6. Recheck file identity and length. Growth beyond the prefix is allowed only when the
   identity and both prefix digests remain equal; shrinkage, replacement, prefix change,
   partial/locked reads, or identity loss rejects the acquisition.
7. Persist the acquisition record before any assessment derives a verdict.

The parser is streaming and offline. It never copies a raw line into output or an error.
`ccusage` and all other external subprocesses remain untrusted and deferred.

### 8.3 Exhaustive output schema

Only these field classes may be emitted:

- schema/parser version and acquisition status;
- session ID, opaque root ID, role, parent/root session IDs, and inclusion reason code;
- file identity digest, frozen length, prefix length/digest, acquisition time, and last
  complete structural-event timestamp;
- structural record count and closed event-type counts;
- cached input, uncached input, output, peak per-call input, model-call count,
  compaction count, truncation count, task duration, and wall-span fields with unit and
  counter-source metadata;
- `loaded_skill_identities` with bytes by identity, or `unknown`;
- `wait_class` counts using `process | agent | external_review | other | unknown`;
- duplicate/incomplete/missing classifications; and
- one content-free error code.

Absent structural evidence is `unknown`, never zero. Skill or wait fields based only on
self-report cannot support a causal claim.

The closed error enum is:

`not_found | root_not_allowed | path_override_required | reparse_rejected |
identity_unavailable | locked_or_partial_read | prefix_changed | file_replaced |
file_shrank | malformed_utf8 | malformed_jsonl | unsupported_schema |
duplicate_conflict | content_field_rejected | sanitized_io_failure | unknown_failure`.

Never serialize raw exception strings, commands, prompts, tool input/output, JSONL
lines, external-tool output, or resolved paths. Phase 1 specification fixtures cover
every enum member plus LF/CRLF, long path, growing file, locked file, invalid UTF-8,
duplicate cumulative records, concurrent readers, root escape, and reparse-point cases.

This bounded specification protects session confidentiality and the provenance of the
efficiency evidence. It authorizes no secret scan, exploit probe, provider call,
credential test, network test, or runtime security programme.

## 9. Compaction drain-state machine

Compaction is a hard rotation trigger when observable. It is not evidence that a lower
token ceiling operated. If the runtime exposes `last_token_usage.input_tokens`, record
its exact source and cut; otherwise use lifecycle/turn/artifact boundaries and make no
token-threshold claim.

When compaction occurs, the current tool call may return. The task classifies the state
exactly once and enters one of these states:

| State | Permitted old-task action | Required successor action |
|---|---|---|
| `clean_safe_point` | Capture exact clean state and hand back | Verify identities and continue the named next action |
| `read_only_atomic_in_flight` | Finish only that already-running bounded read-only operation; capture its raw result identity; hand back | Revalidate the result before interpretation or claim use |
| `mutation_completed_unverified` | Run only read-only identity/diff/status capture; mark all bytes `UNVERIFIED_DO_NOT_COMMIT`; hand back | Inspect exact dirty bytes, reconstruct authority, and run every required validation before edit/commit/use |
| `interpretation_or_draft_incomplete` | Capture partial-byte identity and source list; give no finding, verdict, or claim credit; hand back | Independently redo incomplete interpretation; do not inherit an unreviewed conclusion |

A write/process still executing at the trigger is allowed only to return. Its resulting
state is then classified. A test is `read_only_atomic_in_flight` only when its launcher
and process are proven read-only; otherwise its residue is unverified mutation.

After the trigger, the old task may not start a test, edit, delete, revert, commit, push,
accept, issue a finding, make a claim, remediate, or begin another semantic action.
Calling synthesis or correction a handback does not make it permitted.

The neutral handback records old task ID, required new task ID placeholder, state enum,
exact branch/HEAD/status, dirty/untracked/ignored inventory, changed-byte identities,
completed result identities, incomplete sources, one next action, and hard stops. It may
be written only to a neutral path pre-authorized before the task; otherwise it is
returned in the task final response for the dispatcher to materialize. Candidate or
review artifacts are never edited merely to carry the handback.

Stephen is the only exception owner. An exception must be recorded before the allowed
operation, name one exact maximum operation, and cannot authorize a new finding,
acceptance, remediation cycle, or subject.
