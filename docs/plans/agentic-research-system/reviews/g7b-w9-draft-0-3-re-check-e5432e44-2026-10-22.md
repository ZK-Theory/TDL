## 4. New findings

### Major

#### R-1. `legacy-paper-root` and the transition form a hash cycle

- **Claim.** `legacy-paper-root` key fields include "the transition event ref" (`W9:249`). The full-path mapping's
  "target is a `legacy-paper-root` record" (`W9:250`, `W9:418`). All records are "strict, closed, immutable W2
  objects" (`W9:238`).
- **Evidence.** In the pattern W9 copies (W11 §7.5 and §7.6.2), the mapping binds "the complete target object
  ID/revision/content-hash set", and "a mapping never names its own acceptance/transition"; "a topological sort over
  exact identities/hashes must yield the displayed order" (W11 `11:1399-1402`). W9 §5.1 adopts "no reverse edge"
  (`W9:232`).
- **Failure.** The root record cannot exist before the transition event, because it must contain that event's ref.
  The mapping cannot exist without the root record's content hash, and the transition needs the mapping. That is a
  strongly connected component: the full path cannot be built as specified, or an implementer breaks it with an
  unreviewed mutable field. Recovery has the same problem: the "new `legacy-paper-root` successor record" in §13.1
  (`W9:585`) has no transition event to cite.
- **Impact.** The full path is not constructible; it is the defect class W11's R2–R4 rounds removed.
- **Disposition.** Fix now.
- **Required correction.** Remove "the transition event ref" from `legacy-paper-root`. Its link to the transition
  is projected from `legacy-ownership-transitioned`, which names the root, never the reverse. If the adopted and
  unadopted citation lists can change after transition, move them to a separate citation-status relation that
  points at the root, so the root is not revised. For recovery, say what a recovery root binds instead (the
  predecessor root by lineage and Stephen's recovery Decision).
- **Affects.** §§5.2, 8.2, 13.1; W9-D6; a new test (a cycle between root, mapping and transition is rejected).

#### R-2. §7.3's legacy rule is date-only, and its selector does not fit how `CONVENTIONS.md` actually grows

- **Claim.** A Computational-Log entry is legacy "if its heading date is on or before 2026-07-18". A
  `CONVENTIONS.md` lock is legacy "if it was committed before #126's merge, by the same rule" (`W9:381-387`). Locks
  are addressed by "a heading-anchored entry" (`W9:294`). "No byte of a live legacy entry or lock may differ from
  the baseline" (`W9:391-392`).
- **Evidence.**
  - **Log.** ARS-lane entries predate the freeze. The log has "2026-07-16 -- P00: Gate 5 production
    authority-bootstrap manifest approved -- [DECISION]" (`Computational-Log.md:1986`). The date rule makes it a
    legacy item, subject to import as `closed_reference`, although it is a successor (ARS) decision.
  - **`CONVENTIONS.md`.** `git diff 4b143c92 origin/main -- CONVENTIONS.md` shows 226 insertions and one deletion.
    The hunk `@@ -552,0 +642,117 @@` adds 117 lines **inside** the pre-#126 section "## ARS Foundation Governance"
    (heading at origin/main line 614; the next heading is line 762). Those lines include the post-freeze bullet "A
    governed scientific contract may be accepted by activation plus binding tests ...". The one deletion is the
    footer "*Last updated: 2026-07-16*", which changes routinely.
  - Locks are bullets inside sections, not headings.
- **Failure.** Under the stated rule, "ARS Foundation Governance" is a legacy section. Its heading-anchored bytes
  already differ from any pre-#126 baseline because of legitimate successor additions, so the detector fires on
  every new ARS governance lock. The control then either becomes noise that is routinely bypassed (an 04-plan §7
  stop rule) or the baseline is taken at today's bytes, which certifies post-freeze edits as "legacy". Meanwhile,
  ARS P00 decisions enter the legacy import path.
- **Impact.** The shared-writer exception's one invariant misfires on the real record.
- **Disposition.** Fix now, as part of W9-D9.
- **Required correction.**
  1. Classify by object, not only by date: an entry or lock is legacy if it is about a `legacy_owned` object
     (P01-A/P01-B labels, T-numbered tasks, APM-lane locks) and dates from on or before the freeze. P00/ARS-lane
     entries and the "ARS Foundation Governance" locks are successor regardless of date, and Stephen accepts the
     list.
  2. For `CONVENTIONS.md`, which Git tracks, use the blob at `4b143c92` as the legacy baseline. Select locks at
     bullet or paragraph granularity, and have the repository check require that every later change to a legacy
     section is a pure insertion of successor bullets, never a modification of a legacy bullet. Exclude the footer
     as structural bytes.
  3. Add negative controls for both: a modified legacy bullet is flagged; an inserted successor bullet is not.
- **Affects.** §7.3, §4.4, §5.5; W9-D9; W9-T19.
