## 1. Findings

### F1 (Minor) `research_system/legacy/citations.py:94-95` and record line 320: the `ValueError` fallback leaves the same silent hole, and the record does not say so

`except ValueError: parsed = None` still falls back to raw-text tokens only, so a fully `\u`-escaped result path in a `.json` draft that `json.loads` rejects is silently omitted, with no blocker. This is the exact defect the commit closes for `RecursionError`. Concrete inputs, all returning tokens without the path and raising nothing (probe `probe1.py`, escaped form of `results/a/unique.json`):

- A UTF-8 BOM before otherwise valid JSON (`json.loads` raises "Unexpected UTF-8 BOM"). Windows PowerShell 5.1 `Out-File -Encoding utf8` writes a BOM, a hazard the project already records in memory.
- A valid JSON document containing an integer literal over 4300 digits (`ValueError` from `sys.int_info.default_max_str_digits`). So "not valid JSON" in the record is imprecise: this is valid JSON.
- Any malformed JSON (trailing comma).
- Related, same class, not new: `_iter_json_strings` visits dict values only, so a fully escaped path used as an object key, or in a value shadowed by a later duplicate key, is also not seen.

The record's wording (line 320: "A `.json` draft that is not valid JSON (`ValueError`) is still scanned as raw text only") states the behaviour but not the consequence, and sits under a bullet framed around false blockers. Design note §11.1 ("Citation forms the rule still misses ... for the reviewer's derivation, and a difference then blocks") means the reviewer's derivation is the backstop, which is why this is Minor and not Major.
Change: say plainly that a fully `\u`-escaped path in a `.json` draft that does not decode (BOM, integer over 4300 digits, malformed) is not seen and raises no blocker, and that only the reviewer's derivation covers it. Optionally parse with `text.lstrip("\ufeff")` or `utf-8-sig`, or apply the same refusal to `ValueError`.

Change: either limit the refusal to `drafts/` (a non-draft file goes to the report as an undecodable entry, like `not_text`), or record it as a deliberate departure from §11.1 item 7 and §11.2.
