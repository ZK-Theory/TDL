**accept_with_required_changes.**

### F-4 (Minor): the Gate 6 refusal covers one of the three roots the lock writes, and comes after construction-time mkdirs

- **Claim.** Interpretation 1. `submit` refuses on `self.ledger.control_root` only (`runtime.py:188-190`). The
  lock it then takes writes into three roots: `self.control_root`, `authority_resolver.control_root` and the ledger
  root (`:191-195`).
- **Construction writes.**
  - `LegacyRuntime.__init__` builds `ReceiptStore(control_root)` (`:159`), which runs `mkdir` on `receipts/`,
    `runtime/` and `receipts/idempotency` (`store/receipts.py:197-203`). That happens before any refusal.
  - `EventLedger(...)` runs `mkdir` by default (`store/ledger.py:257-259`), and binding happens wherever the
    caller builds the ledger.
- **Design text.** §7.2 says the refusal runs "when `LegacyRuntime` binds a store … only then bind". The code
  leaves "only then bind" to every future caller. Today the read-only CLI orders it correctly (`cli.py:1507-1515`),
  and no mutating caller exists.
- **Failure scenario.** A WP9.3 mutating CLI builds the ledger and runtime on the Gate 6 control root, then calls
  `submit`. The refusal fires, but `mkdir` has already run in the Gate 6 root. Separately, a caller passes a scratch
  ledger with `control_root` set to the Gate 6 root: the refusal passes, and the lock writes a lease into the Gate 6
  root.

  On the real store the directories already exist, so `mkdir` is very likely a no-op. That is luck, not a
  control.
- **Test blind spot.** The W9-T20 byte-identity check `_tree_bytes` (`test_w9_legacy_runtime.py:123-124`) lists
  files only, so a created empty directory is invisible to it.
- **Disposition.** Fix now (small), or defer with a dependency recorded for WP9.3.
- **Proposed change.**
  - Refuse on each distinct lock root, or require `self.control_root == ledger.control_root` and refuse both.
  - Build `ReceiptStore` lazily inside `_submit_authorized`.
  - Expose a `LegacyRuntime.open(control_root, …)` factory that runs `refuse_gate6_store` before `EventLedger`
    and `_verified_ledger`, and record that WP9.3's CLI must use it.
  - Make `_tree_bytes` include directories.
- **Affects.** §7.2, W9-T20, contract `forbidden` ("any write to the Gate 6 store"), WP9.3.

### F-8 (Minor): G5's replay half stops short of the subject binding; record the preparer obligations

- **Claim.** Interpretation 2. Replay binds a resolved record to its open proposal (ID and exact content) and to
  the resolving Decision's ID (`reducers.py:258-279`). It does not check two catalogue rules:
  - that the resolving Decision's proposal named this record as its subject, which G5 requires ("its subject is

### F-9 (Minor): `_add_edges` is quadratic and can escape as `RecursionError`

- **Evidence.** `reducers.py:120-144` copies the whole graph on every edge set and runs a recursive DFS over every
  node. A reference chain longer than Python's recursion limit (about 1,000) raises `RecursionError`. That is not
  an `IntegrityError`, so it escapes `LegacyRuntime._replay`'s wrapper (`runtime.py:241`).
- **Disposition.** Accept risk now, since no routed row adds edges in v1. Fix when WP9.4 or WP9.6 routes roots and
  mappings: use an iterative reachability check from the new source only.
