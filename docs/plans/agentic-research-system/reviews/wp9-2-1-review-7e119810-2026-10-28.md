## 2. Findings

### m-1 (Minor, required): the envelope's negative controls do not exercise the byte guard

1. **Claim.** The positive test's guard is
   `assert data == canonical_bytes(expected_envelope())` (`tests/research_system/contracts/test_w9_acceptance_envelope.py:166`).
   The three controls compare against `canonical_bytes(expected_envelope())` or `_committed()` directly
   (`:178`, `:180`, `:247`). None of them calls the guarded comparison, and no shared predicate links them to it. Each
   control proves that two different byte strings differ, which is true whatever line 166 says.
2. **Evidence.** The record says a tampered hash or a changed ref "passes the schema but fails the byte check" and that
   "a re-encoding fails it" (`wp9-2-1-record.md:80-83`). The precedent factors the guard into one predicate that the
   positive test and every control call: `_is_b1_main_output` and `_is_o8_accepted`
   (`test_w9_expected_catalogue.py:396-413`, `:442-444`). The B2 confirmation checked each control with its guard removed
   (`wp9-1-stage-b2-confirmation-3241f0e9-2026-10-27.md`, Mode line).
3. **Failure scenario, run.** I built five scratch mutants of the test file (§5). Two are the key ones. In the first,
   line 166 is weakened to `json.loads(data) == expected_envelope()`, line 165 is removed, and the envelope is
   pretty-printed or has `\r\n` appended. In the second, the guard is replaced by `pass` and the envelope's
   `owner_row_multiset_hash` is all zeros. In both, the positive test and **all three controls pass**. With the guard
   intact and a pretty-printed envelope, only the positive test fails, so today the guard works and the controls add
   nothing.
4. **Impact.** If a later edit weakens the guard to an object comparison, nothing in the suite notices. This is the shape
   of obs 2026-10-27-gate-pass-set-wider-than-accepted-identity: a gate that compares objects when the owner accepts
   bytes. WP9.2-2's genesis guard 6 re-hashes the raw file against `ACCEPTED` (note §7.3 item 6), so a runtime check will
   exist after WP9.2-2. Until then, this test is the only binding.
5. **Disposition.** Fix now, in WP9.2-1.
6. **Proposed change** (keep the derivation as it is):

   ```python
   def _is_derived_envelope(data: bytes) -> bool:
       return data == canonical_bytes(expected_envelope())


   def test_committed_envelope_is_the_derived_envelope() -> None:
       assert _is_derived_envelope(_committed())


   def test_byte_identity_refuses_what_the_schema_admits() -> None:
       committed = _committed()
       tampered = json.loads(committed)
       tampered["owner_row_multiset_hash"] = "0" * 64
       assert _valid(tampered)
       assert not _is_derived_envelope(canonical_bytes(tampered))
       assert not _is_derived_envelope(json.dumps(json.loads(committed), indent=2, sort_keys=True).encode())
       assert not _is_derived_envelope(committed + b"\n")
       assert not _is_derived_envelope(committed + b"\r\n")
   ```

   In `test_a_changed_ref_breaks_the_envelope` (`:243-247`), assert `not _is_derived_envelope(canonical_bytes(envelope))`.
   Once the predicate is exact, line 165's `b"\n" not in data` is redundant, because `json.dumps` escapes every newline
   inside a string. Keep it or drop it. Correct the record's §3 bullets to match. Then re-run the guard-removal mutants
   and confirm each control fails.
7. **Affected:** WP9.2-1 only.

### m-2 (Minor, owner choice): the amended `forbidden` list says nothing about genesis or live operations outside a scratch store

1. **Claim.** The amendment drops "W9 genesis import" from `forbidden`, as note §6.2 directs (`wp9-2-design-note.md:356-359`).
   Nothing replaces it. Of the remaining entries (`w9-materialization-bootstrap-contract.yaml:66-72`), only the Gate 6
   store line and `refused_store_identities` (`:20-21`, `:43`) limit where genesis may run. P-076 still withholds
   "creating a real store, running genesis on one, issuing a grant on one" and "any write to a legacy file"
   (`03-decisions-and-open-questions.md:4810-4815`). 06v places W9 genesis at L-3 (`06v-w9-implementation-plan.md:596`).
2. **Evidence.** Before the amendment, "W9 genesis import" forbade genesis outright. After it, the contract permits the
   code, which is right, and it no longer records that running the code on a real store needs a later decision. That
   rule now lives only in P-076 and 06v §7.
3. **Failure scenario.** At O-3, Stephen accepts this text as the contract the runtime runs under, and WP9.2-2 pins its
   bytes. A later reader, or an agent preparing L-3, reads a `forbidden` list that bars only the Gate 6 store. The
   contract is not wrong. It is incomplete in the place a reader would look first.
4. **Impact.** Record clarity only. No code reads `forbidden`, and P-076 remains the operative authority. The rule
   "legacy writes" was never in the contract, apart from "observation, adoption, transition, cutover, or retirement of
   any legacy item" (`:71`). That entry is kept, so legacy writes are no weaker than before.
5. **Disposition.** Owner choice, before O-3. Adding the line after O-3 costs a further amendment, a re-acceptance and a
   change to the WP9.2-2 pins. Adding it now costs one line and a new contract identity in the record's §1 table.
   - **(a) Recommended:** add the line in WP9.2-1. It departs from note §6.2's exact list, so the record names the
     departure.
   - **(b)** Accept the list as it stands. P-076 and 06v §7 L-3 stay the operative bar.
6. **Proposed text** for `forbidden`. It refers to the owner decision instead of restating it, so it stays true after
   L-3 is authorized:
   `- W9 genesis or any live operation L-0 to L-5 on a store other than a test-created scratch store, and any write to a legacy file, without the owner decision that authorizes it (P-076)`
7. **Affected:** WP9.2-1 (the contract bytes and the record's §1 table); O-3; WP9.2-2 (the `bootstrap_*` pins in
   `accepted_w9.py`). The genesis payload's `verification_requirements` copy `verification_rules` only, so this line
   would not appear there.

### m-3 (Minor, recommended): no test pins the amended free-text lists

   exact `forbidden` and `verification_rules` lists, as W11 does. Alternatively, defer to WP9.2-2, whose `ACCEPTED`
