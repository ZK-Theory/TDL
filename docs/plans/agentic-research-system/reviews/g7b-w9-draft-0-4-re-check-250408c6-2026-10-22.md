## 4. New findings

### Minor

- **s-1. The recovery root and its Decision need a defined order (`W9:615-616`).** The recovery root "binds the
  predecessor root and Stephen's recovery Decision". If that Decision names the recovery root it accepts, the two
  form a cycle, the same class as R-1. Follow W11's content-before-acceptance pattern: the recovery Decision names
  only the predecessor root and the recovery intent, and the recovery root names that Decision. Alternatively, the
  recovery root is content that a later Decision accepts and that does not itself name the Decision. Either is fine;
  the text should pick one. W9-T21 can cover it.
- **s-2. Manual-mode Git commits need verifiable attribution (`W9:619-621`).** The ruleset protects only `main`, and
  a Git author field is self-declared. A "named branch" carrying the human writer's edits proves nothing about who
  made them. Require signed commits by the named writer, or pushes whose GitHub actor identity is recorded, so the
  later import can verify attribution instead of trusting the author line.

- **I-a.** The `CONVENTIONS.md` rule passes on today's tree (§3, R-2 row). This is direct evidence that the
  insertion-only rule matches how the file has grown, not only a design claim.

  bypass `RepositoryRole` 5 in `pull_request` mode, `required_approving_review_count: 0` and
  `require_code_owner_review: true`. These match `W9:195` and the reconciliation §7.
