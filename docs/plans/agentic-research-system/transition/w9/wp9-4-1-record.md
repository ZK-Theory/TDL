## 3. Readings and departures

### Departures

- **`LR-033` open-item membership check (`research_system/legacy/preparers.py:650-656`):** `prepare_decision_proposal` calls `_check_discharge_open_item(environment, record, expected_blob=blob)`, which verifies both that `legacy-open-items.json` at `git_head` has Git blob `expected_blob` **and** that the discharge record's `(item_kind, item_id)` appears in that file. WP9.4 design note §8 (`wp9-4-design-note.md:728-729`) specifies only the blob match at LR-033 and checks item presence at LR-030 and LR-034. This tightening rejects an unresolvable Decision proposal early (for instance if `git_head` moved to a committed open-item list that dropped the item between LR-030 and LR-033) while admitting every valid proposal that could pass LR-034.
- **Refusing `OWNER` as named reviewer across all W9 review requests (`research_system/legacy/runtime.py:492-497`):** Inside `_submit_locked`, `RequestW9AuthorityReview` now refuses before shadow replay and before any write when `payload.get("reviewer_actor_id") == authority_evidence.administration_context.owner_actor_id` (`"W9 review request names the owner as reviewer"`). Previously a request could name the bound owner and burn the one review reservation before `LegacyRuntime._require_role` (`runtime.py:646-647`) refused the owner's verdict. Because `RequestW9AuthorityReview` handles WP9.3 rows (`LR-007`, `LR-012`, `LR-017`) as well as `LR-026` and `LR-031`, this changes accepted WP9.3 behaviour — though only to refuse a request that no verdict could ever complete.

### Readings

- **R1 (`LR-027` / `LR-032` `_shadow` before `_require_role` ordering, `research_system/legacy/runtime.py:498-499`):** `_submit_wp9_3` calls `self._shadow(...)` before `self._require_role(...)`. When `OWNER` submits a verdict on a review naming another actor (`store.actors.reviewer`), `_shadow` raises `_check_verdict`'s mismatch message (`"W9 verdict is not recorded by the reviewer the request named"`) first; `_require_role` enforces `"W9 LR-027/LR-032 refuses the owner"` separately via `RESOLVER_ROWS` when tested with a matching reviewer/actor boundary.
- **R2 (`W9-T9` suspension cause precedence, `research_system/legacy/projection_read.py:85-86`, `:118-122`; note §7 M-1):** Re-observing a modified JSON source requires committing an updated membership table covering the new bytes (`reducers.py:1782-1788`) and places the prior observation in `state["stale_observations"]` (`reducers.py:1861-1869`). Because `adoption_suspension_cause` checks `stale_observations` (`projection_read.py:85-86`) before scanning later observations (`projection_read.py:118-122`), both new-blob re-observation controls in W9-T9 (same-family and disjoint-family) yield `cause == "observation_stale"`, whereas same-family re-observation at the unchanged blob yields `cause == "later_observation"`.
- **R3 (`06v-addendum-2026-11-10-w9-paths.md:31`):** Line 31 is re-cited with `LEGACY_OPEN_ITEMS`, `evidence.py:44` and `LEGACY_OPEN_ITEMS_FORMAT`, `evidence.py:45`, as directed by that file's 2026-11-20 amendment (`:65-67`) and Handover §4. Existing rows on lines 28–30 (`evidence.py:39`, `:42`, `:43`) did not shift.
- **R4 (Oversized-integer `ValueError` on evidence JSON files, `research_system/legacy/evidence.py:71-88`, `:422`):** `_parse_evidence_json` catches `(UnicodeDecodeError, ValueError)` rather than `(UnicodeDecodeError, json.JSONDecodeError)` so integers exceeding CPython's digit limit (around 4,300 digits) raise the documented `EvidenceRefused("W9 evidence file is not JSON: <path>")` instead of an uncaught `ValueError` traceback on the CLI. Because `read_evidence` serves every W9 evidence file (WP9.3 and WP9.4), the change reaches every W9 evidence read; recorded as a reading rather than a departure because it only turns an unhandled runtime exception into the documented refusal without raising CPython's limit.
- **R5 (Evidence reads ignore Git replacement refs, `research_system/legacy/evidence.py:71-79`, `:166`):** Every Git call in `evidence.py` passes `--no-replace-objects`: `read_evidence`'s and `require_open_items`' `git show`, `blob_at`'s `rev-parse`, and `is_ancestor`'s `merge-base --is-ancestor`. A local `refs/replace` entry therefore cannot make an evidence read return bytes, a blob or an ancestry that differ from what is committed at `git_head`. This is the same rule `research_system/git_execution.py:108` applies with `GIT_NO_REPLACE_OBJECTS`. The flag is passed in `evidence.py`, not in `reader._git`, because `reader.py` is one of `IMPORTER_MODULES` (`reader.py:41`) and its blob is part of the importer identity. The change reaches every W9 evidence read, WP9.3's included. It is recorded as a reading, not a departure, because it only stops a local ref from changing what a read at `git_head` returns.
