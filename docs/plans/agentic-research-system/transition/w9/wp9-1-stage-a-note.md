## 2. Two deviations from 06v WP9.1, for review

1. **Two stages, following W11's precedent.** W11 materialized its schemas inert first, then its catalogue. Its
   bootstrap contract records `expected_catalogue: forbidden_in_pr1`. The W9 catalogue's schema rows pin each schema
   file by Git commit and blob, so the catalogue can only be written after the schemas are committed. **Stage B** adds
   the catalogue (LR rows), the acceptance-envelope instance and a materialization verifier, and ends with Stephen's
   acceptance of the catalogue identity. Stages A and B can land as one PR or as two (D-6).
2. **No separate event schemas.** 06v WP9.1 says "one … schema per W9 §5.2 record and per emitted event". W11's
   materialized family has no event schemas: its catalogue rows name events as `E:` tokens, and at runtime events fall
   back to `ars://core/event` 1.0.0 (06v §2.2, `runtime.py:588-613`). Stage A follows that precedent, and stage B's
   catalogue rows name every W9 event. If the reviewer or Stephen prefers dedicated event schemas, they can be added
   in stage B.

## 3. Choices a reviewer should check

- **Restricted sources.** A `restricted_untracked_file` source identity has no frozen-copy field at all (W9 §5.4;
  W9-T11, schema half).
- **Paper root.** `legacy-paper-root` has no transition or citation-status field, so a reference cycle cannot be
  expressed (W9-T21, schema half). Its paper key binds its root path.
- **Ownership modes.** `legacy-ownership-transitioned` admits only W9 §8.2's three transitions. A transition to
  `successor_owned` requires a mapping and a paper-root reference (W9-T5, schema half).
- **Signed classes.** Each W0 class on an observation family requires a signed W0 revision reference and a
  signature-record reference (W9 §1 item 6).
- **Inventory rows.** A blocker row requires a blocker reason, and an item row cannot carry one (W9 §5.5;
  `w9-segmentation/1.0.0` §4).
- **Closed-reference acceptance.** Each item carries its `pilot_promotion` fixture IDs, evidence and waiver
  reference (O-37), plus the threshold and governing-record hashes and their anchors (O-25).
- **Registration bindings.**
  - The `successor_results_root` role binds `results/ars/` and `successor_owned`.
  - `conventions_lock` binds `CONVENTIONS.md` at the repository root; the vault alias is unregistrable.
  - The manuscript-root role binds the two P01 roots.
  - Paths that traverse (`..`) or are absolute are rejected.
