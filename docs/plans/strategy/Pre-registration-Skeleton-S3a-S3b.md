# Pre-registration Skeleton: S3a/S3b Lean-certified finite-complex reductions

Date: 2026-07-07
Status: Draft for execution
Strand: Lean / TDA / large finite simplicial complexes
Depends on: S0 PASS, S1 COMPLETE, S2 assurance-lane pilot preferably complete
Primary framing: B - verified exact reduction
Secondary fallback: C1 - Euler/local finite-complex invariants only

## 1. Registration decision

Pre-register a two-stage spike:

1. **S3a: finite simplicial-chain bridge prototype**
2. **S3b: elementary-collapse preservation theorem**

The spike is not allowed to attempt full persistent homology, full discrete Morse theory, barcode theory, interleaving distance, bottleneck distance, or the stability theorem.

The intended contribution is narrower:

> Build the minimal Lean bridge from `AbstractSimplicialComplex` to finite simplicial chain objects, then prove that one elementary free-face reduction preserves a target invariant, initially Euler characteristic and, if feasible, homology over `ZMod 2`.

## 2. Research question

Can the Lean/mathlib stack support a useful verified reduction theorem for finite abstract simplicial complexes quickly enough to justify using Lean as a formal-assurance lane for large-complex TDA preprocessing?

More concretely:

> Given a finite abstract simplicial complex `K`, can we formalise an elementary collapse removing a free face `σ` and its unique coface `τ`, and prove in Lean that the reduction preserves Euler characteristic, with homology preservation over `ZMod 2` as the stretch target?

## 3. Hypotheses

### H1: chain bridge feasibility

A usable finite-chain prototype can be built over `ZMod 2` for `AbstractSimplicialComplex ι`, assuming finite vertex type or finite support conditions.

Minimum acceptable result:

> Define dimension-indexed chain groups generated by `n`-simplices of `K`, define the mod-2 boundary map, and prove enough boundary compatibility to package or approximate a chain-complex object.

Preferred result:

> Define a genuine `HomologicalComplex` or compatible chain-complex object whose differential is the simplicial boundary and whose `d_comp_d` proof is accepted by Lean.

### H2: Euler preservation feasibility

An elementary free-face collapse can be formalised and shown to preserve the finite alternating face-count Euler characteristic.

Minimum acceptable result:

> If `K'` is obtained from `K` by removing exactly one `k`-simplex and exactly one `(k+1)`-simplex, and all other face counts are unchanged, then `χ(K') = χ(K)`.

Preferred result:

> Define the elementary-collapse operation itself and prove the face-count change theorem from the collapse hypotheses.

### H3: homology preservation feasibility

If S3a succeeds cleanly, the elementary collapse should be formalised as a chain equivalence, chain homotopy equivalence, or quasi-isomorphism over `ZMod 2`.

Minimum acceptable result:

> Produce a precise theorem statement and partial supporting lemmas showing the route to homology preservation.

Preferred result:

> Prove that the collapse induces isomorphic homology groups or a quasi-isomorphism of chain complexes.

## 4. Non-goals

The coding agent must not work on the following unless explicitly instructed in a later spike:

* Persistent homology.
* Persistence modules.
* Barcodes or persistence diagrams.
* Interleaving distance.
* Bottleneck distance.
* Vietoris-Rips filtrations.
* Cech complexes.
* Full discrete Morse theory.
* Full Forman gradient vector fields.
* General coefficients over arbitrary rings.
* Geometric simplicial complexes unless needed only for reference.
* Implementation-level optimisation of the empirical TDA pipeline.

The spike is about a small verified mathematical kernel, not production TDA software.

## 5. Formal setting

### Preferred Lean object

Use:

```lean
AbstractSimplicialComplex ι
```

as the primary complex type.

Do not replace it with a custom simplicial-complex definition unless mathlib's type blocks the spike completely. If a custom toy type is needed for exploration, it must remain in a clearly marked scratch file and must not count as a promoted result.

### Vertex assumptions

Start with the smallest workable assumptions.

Preferred first assumptions:

```lean
[DecidableEq ι]
[Fintype ι]
```

Add `[LinearOrder ι]` only if ordering is needed for indexing faces or defining signs. Since the first chain target is over `ZMod 2`, orientation signs should be avoided if possible.

### Coefficient field

Use:

```lean
ZMod 2
```

for the first homology-oriented prototype.

Rationale: over `ZMod 2`, the simplicial boundary can be defined by summing codimension-one faces without orientation signs. The proof of `∂^2 = 0` reduces to showing each codimension-two face appears twice.

Do not attempt general coefficient rings in S3.

## 6. S3a: finite simplicial-chain bridge

### S3a objective

Construct a minimal Lean prototype connecting a finite abstract simplicial complex to dimension-indexed chain groups and boundary maps over `ZMod 2`.

### S3a required definitions

The agent should attempt the following definitions, in this order.

#### Definition 1: n-simplex subtype

Define the type of `n`-simplices of `K`.

Intended mathematical meaning:

```lean
Simplex K n = {s // s ∈ K ∧ s.card = n + 1}
```

Exact Lean syntax may differ depending on mathlib's representation of faces.

Acceptance condition:

* The type compiles.
* The membership condition uses the existing `AbstractSimplicialComplex` API.
* The dimension/cardinality convention is documented.

#### Definition 2: chain group

Define the `n`-chain module over `ZMod 2`.

Preferred mathematical meaning:

```lean
Chain K n = Simplex K n ->₀ ZMod 2
```

or an equivalent free module construction supported by mathlib.

Acceptance condition:

* The object has an additive commutative group structure.
* The object has a `Module (ZMod 2)` instance.
* Basis elements corresponding to simplices can be constructed.

#### Definition 3: face deletion

For an `(n+1)`-simplex `s`, define its codimension-one faces by deleting one vertex.

Required behaviour:

* Each deleted face belongs to `K` by downward closure.
* Each deleted face has cardinality `n+1`.
* The construction gives an element of `Simplex K n`.

Acceptance condition:

* At least one lemma proves that deleting a vertex from a simplex gives a lower-dimensional simplex.
* The lemma should not rely on unproved `sorry`.

#### Definition 4: boundary map

Define:

```lean
boundary K n : Chain K (n+1) ->ₗ[ZMod 2] Chain K n
```

Mathematical meaning:

```text
∂(s) = sum of all codimension-one faces of s
```

over `ZMod 2`.

Acceptance condition:

* The map is linear.
* It is defined on basis simplices and extended linearly.
* It compiles without `sorry`.

#### Definition 5: boundary squared

Prove:

```lean
boundary K n ∘ boundary K (n+1) = 0
```

or the closest type-correct formulation.

Mathematical proof route:

* A codimension-two face of an `(n+2)`-simplex is obtained by deleting two vertices.
* Each unordered pair of deleted vertices appears in exactly two deletion orders.
* Over `ZMod 2`, the two contributions cancel because `2 = 0`.

Minimum acceptable fallback:

* Prove the statement for low dimensions, preferably `n = 0` or `n = 1`.
* Clearly document the obstruction to the general proof.

Preferred result:

* General proof for all `n`.

## 7. S3b: elementary-collapse preservation theorem

### S3b objective

Formalise one elementary free-face collapse and prove preservation of at least Euler characteristic, with homology preservation as the stretch target.

### S3b mathematical definitions

Let `K` be a finite abstract simplicial complex.

Let `σ` be a `k`-simplex and `τ` be a `(k+1)`-simplex.

`σ` is a free face of `τ` if:

1. `σ ⊂ τ`;
2. `τ ∈ K`;
3. `σ ∈ K`;
4. `τ` is the unique coface of `σ` in `K`;
5. removing `σ` and `τ` leaves a valid abstract simplicial complex.

The reduced complex is:

```text
K' = K \ {σ, τ}
```

where this is understood as removal from the face set, not merely vertex-set subtraction.

### S3b required theorem 1: Euler preservation

First target theorem:

```text
If K' is obtained from K by removing exactly one k-simplex σ
and exactly one (k+1)-simplex τ, with all other simplex counts unchanged,
then χ(K') = χ(K).
```

This theorem may be proved before the full collapse operation is implemented.

Expected proof:

```text
χ(K') = χ(K) - (-1)^k - (-1)^(k+1)
      = χ(K)
```

because:

```text
(-1)^k + (-1)^(k+1) = 0.
```

Lean implementation may use integers for Euler characteristic.

Minimum acceptable version:

* Define a finite face-count Euler characteristic.
* Prove preservation from explicit face-count assumptions.

Preferred version:

* Prove those face-count assumptions from the elementary-collapse definition.

### S3b required theorem 2: reduced complex validity

If the agent implements `K'` directly, it must prove:

```text
K' is an AbstractSimplicialComplex.
```

Required proof idea:

* Any face of a remaining face is still in `K`.
* It cannot be one of the removed faces unless the collapse hypotheses are violated.
* The free-face and maximal-coface hypotheses prevent downward-closure failure.

Minimum acceptable fallback:

* State the validity theorem precisely.
* Explain which condition is missing if Lean proof fails.
* Do not pretend that a raw set subtraction is automatically a simplicial complex.

### S3b stretch theorem: homology preservation

Only attempt this after S3a and Euler preservation succeed.

Target theorem:

```text
The inclusion K' -> K induces an isomorphism on homology over ZMod 2.
```

Acceptable formal alternatives:

* `K'` and `K` have chain homotopy equivalent chain complexes.
* The inclusion chain map is a quasi-isomorphism.
* The quotient chain complex `C(K) / C(K')` is acyclic.
* The two-dimensional subcomplex generated by `σ` and `τ` forms an acyclic summand.

Preferred proof route:

1. Decompose `C(K)` as `C(K') ⊕ A`, where `A` is generated by `σ` and `τ`.
2. Show `A` is acyclic because `∂τ = σ + other terms`, and under the correct adapted basis or quotient argument the collapse pair contributes no homology.
3. Conclude homology preservation.

Warning:

The naive two-generator proof may fail if `∂τ` contains other faces. The coding agent must not erase this issue. If using the quotient route, it must show precisely why the pair becomes acyclic modulo `K'`.

## 8. Artefact contract

Every promoted Lean artefact must satisfy:

1. `lake build` exits with status `0`.
2. No `sorry`.
3. No `admit`.
4. No `by aesop` or similar opaque hammer-only proof unless the proof is short and auditable.
5. Axiom audit completed.
6. No new axioms.
7. Any use of classical choice is documented.
8. The theorem statement has a plain-English referent note.
9. The theorem statement is independently reviewed before being treated as evidence.
10. Scratch files are separated from promoted files.

A promoted result is not valid merely because a Lean file compiles. It must compile and prove the intended mathematical statement.

## 10. Coding-agent execution instructions

The coding agent must follow this order.

### Step 1: environment check

Run:

```bash
lake build
lake exe cache get
lake build
```

Record toolchain version, mathlib commit, and build status in `S3a/build.log`.

### Step 2: inspect APIs

Before writing definitions, inspect existing mathlib APIs for:

* `AbstractSimplicialComplex`
* face membership
* subfaces/downward closure
* finite sets / `Finset`
* finitely supported functions
* free modules
* `ZMod 2`
* `HomologicalComplex`
* Euler characteristic, if relevant

Record useful names in `S3a/README.md`.

### Step 3: build the n-simplex subtype

Do not proceed to boundary maps until the `Simplex K n` type compiles and has basic membership/cardinality lemmas.

### Step 4: build chains

Use finitely supported functions or the most direct mathlib free-module representation.

Do not introduce a custom algebraic structure unless mathlib's standard module path fails.

### Step 5: define boundary

Define boundary over `ZMod 2`.

Avoid oriented signs in S3a unless absolutely necessary.

### Step 6: prove boundary compatibility

Try the general `∂^2 = 0` proof.

If it fails, produce a low-dimensional proof and a precise obstruction report.

### Step 7: define Euler characteristic

If existing mathlib Euler characteristic can be reused cleanly, use it.

If not, define the finite face-count Euler characteristic:

```text
χ(K) = Σ_n (-1)^n * number_of_n_simplices(K)
```

bounded by the finite vertex cardinality.

### Step 8: prove Euler preservation

First prove from explicit face-count assumptions.

Then, if feasible, prove those assumptions from elementary-collapse hypotheses.

### Step 9: attempt homology preservation only if ready

Do not start homology preservation unless S3a and Euler preservation compile cleanly.

If attempted, begin with theorem-statement design and a quotient/acyclic-summand proof plan.

### Step 10: produce result files

Each result file must separate:

* proved results;
* compiled definitions;
* failed attempts;
* mathematical obstacles;
* Lean/API obstacles;
* recommended next spike.

## 11. Stop rules

Stop S3a if, after the timebox, none of the following compiles:

* `Simplex K n`;
* `Chain K n`;
* boundary on basis simplices;
* any low-dimensional boundary lemma.

Stop S3b if Euler preservation from explicit face-count assumptions cannot be proved.

Stop the homology stretch immediately if it requires building a large missing homological-algebra API rather than using existing mathlib machinery.

Do not continue by expanding scope into persistence.

## 12. Promotion criteria

### Promote S3a if

At least the following compile:

1. `Simplex K n`;
2. `Chain K n`;
3. boundary map over `ZMod 2`;
4. either general `∂^2 = 0` or a clearly documented low-dimensional prototype.

### Promote S3b if

At least the following compile:

1. finite Euler characteristic or reuse of mathlib Euler characteristic;
2. face-count change theorem;
3. Euler preservation under elementary-collapse-shaped assumptions.

### Promote S3b as a strong success if

In addition to Euler preservation:

1. the reduced complex is constructed as an `AbstractSimplicialComplex`;
2. the collapse hypotheses imply validity of the reduced complex;
3. homology preservation is either proved or reduced to a precise acyclicity lemma.

## 13. Failure interpretation

Failure of homology preservation is not a failure of the spike if Euler preservation and the chain bridge succeed.

Failure of full `AbstractSimplicialComplex -> HomologicalComplex` packaging is not a failure if the core definitions and boundary lemmas compile.

Failure of S3a is informative if it identifies a specific missing mathlib abstraction, such as orientation handling, finite free-module indexing, or subcomplex construction.

The only hard failure is producing a toy formalisation that cannot be connected back to `AbstractSimplicialComplex`.
